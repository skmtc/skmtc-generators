# Retro: #154, every generator on core 0.58.1 without rootRef (PR #155)

## 1. Summary

#154 asked us to move every stock generator to core 0.58 and to remove `rootRef`, which core 0.58.0 removed (skmtc/skmtc#494). PR #155 pins core 0.58.1, lang-typescript 0.15.18 and lang-kotlin 0.11.52. It gives the 16 published packages one patch bump each, and it removes all 195 `rootRef` lines and 23 unused `RefParts` imports from 44 files. It merged as fe50d58, and all 16 packages are on JSR.
Output on core/_schemas is byte-identical: 38,013 files from main against the branch, and about 35,900 files from the published old releases against the new ones.
The run took 24m 03s, with 21m 30s of agent time. It used 27,304 input tokens, 16.39M cached tokens and 72,496 output tokens, at an estimated $8.44.
`implement` cost the most: 11m and $4.22. Most of it went on a before-and-after dump harness written from scratch. The proof was worth having, but the harness should not have to be rewritten each run.

## 3. Keep

- Break each guard on purpose and restore it: a core pin set back to 0.57.0 fails `workspace.test.ts:47`/`:100`, and a re-added `rootRef` fails the new test. Already in finish.md §4.
- A scripted mechanical removal that throws on any line it cannot classify, then a read of `git diff` for the non-deletion lines only. It made 195 edits in seconds and kept each file's comma style. Write it in the skmtc-generator skill's finish.md, next to §5.
- The follow-on compared the published old and new releases from jsr.io, which closes the gap a workspace-only comparison leaves.

## 4. Deferred

- `ValibotRef.rootRef` and `toTsValue`/`toZodValue`/`toValibotValue`/`toArktypeValue` args are gone in patch releases. A user's cloned generator that still passes `rootRef` fails `deno check` on upgrade. Self-review dismissed this, because the ticket asked for patch bumps.
- gen-arktype `ArktypeObject.ts:163 toKeySyntax` (12) and gen-kotlin-jackson `toSegments` (20), `walkSchema` (12) and `toOperationRootedName` (11) are over the complexity limit on main. Anyone who runs finish.md §1 on these packages meets this. Found in implement.
- Root `deno fmt --check` drift and the root `check`/`publish` task gaps (#59) are as on main. An agent who trusts `deno task check` or runs `deno fmt` meets them.
- Name collisions leave some generator and document pairs with no output, on both sides: cloudflare.json for most generators, and cloudflare, openrouter and remote-com for Kotlin. Users with those documents meet it. Seen by follow_on; causes not investigated.
- stripe.json gives 0 files for gen-arktype and gen-shadcn-form, and only 1 file for gen-express and gen-supabase-hono. Stripe users meet it. Seen by implement and follow_on; causes not investigated.
- `/tmp/skmtc154` (logs, dump and pin scripts) is left on the host. The next run on this machine may find it.
