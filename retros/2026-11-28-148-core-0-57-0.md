# Retro: #148, every generator on core 0.57.0 (PR #149)

## 1. Summary

#148 asked us to move every stock generator to core 0.57.0, which orders a run by generator kind (skmtc/skmtc#490). PR #149 pins core 0.57.0, lang-typescript 0.15.16 and lang-kotlin 0.11.50, and gives the 16 published packages one patch bump each. No generator code changed. It merged as 9fae015, and the publish run put all 16 packages on JSR. In a fresh project, the follow-on resolved one copy of core and showed that the operation/model order in a config no longer changes the output bytes.
The run took 11h 02m, but only 8m 16s of that was agent time. It used 21,177 input tokens, 6.05M cached tokens and 43,508 output tokens, at an estimated $5.51.
`light_check` cost the most: 10h 53m and $2.08. Its first visit waited 10h 50m on a tool permission prompt that nobody could answer. The retry ran with read-only commands and finished in about a minute. The wait was not worth it. `implement` cost $1.90 in 4m 19s, against 10m and $2.68 for the same kind of change in #145.

## 4. Deferred

- Root `deno.json` `tasks.publish`: gen-shadcn-form comes before gen-shadcn-select, which it depends on, and gen-fetch-example is not in the list. A maintainer who publishes by hand meets this. Found in self-review and the follow-on; see #59.
- Root `deno.json` `tasks.check`: gen-md-docs, gen-fetch-example, gen-kotlin-jackson and gen-kotlin-spring are not checked. An agent who trusts `deno task check` meets this. Found by the follow-on; see #59.
- PR #149 body: "all 19 members" should say 18 members (19 files with the root). Readers of the PR meet it. Found in the light check.
- `test-support/test/workspace.test.ts` does not assert one patch bump per published package. Reviewers check it against JSR by hand on every pin move. Found in the light check; first logged in the #145 retro.
- Root `deno fmt --check` reports 469 unformatted files that this change did not touch. CI does not gate on it. An agent who runs `deno fmt` gets a huge diff. Found in implement.
- Running every generator in one project fails with "Registered definition mismatch": gen-zod and gen-valibot both write `user`, and the two TanStack Query generators write the same hooks. A user who installs alternative generators together meets it. Found by the follow-on, and not compared against the 0.55.1 releases.
- `.github/workflows/publish.yml`: `actions/checkout@v4` warns that it targets the deprecated Node.js 20. The publish job breaks when GitHub removes Node 20. Found by the follow-on in run 46132094440.
- Not measured: the output change from the ticket's note on a real project, and a type check of the generated output after the release. Users with an operation generator listed before a model generator meet the change on their first run.
- jsr.io returned HTTP 403 to Python urllib; curl works. An agent who queries JSR metadata from Python meets this. Found by the follow-on.
